# Core preservation illustrative glossary

This is an illustrative, unregistered context. Its decision IDs are examples
of the reference format only; it is not an approval record for a product.

| Term | Meaning | Avoid as a synonym | Example |
| --- | --- | --- | --- |
| Rule catalog | The governed collection of recorded rules for a context. | Rule list | The catalog preserves an approved rule and its approval information. |
| Recorded rule | A rule entered in the catalog with its stable identity and governance details. | Note | A recorded rule can be proposed, approved, or deprecated. |
| Approved rule | A recorded rule that an approving decision has authorized. | Accepted note | An approved rule has an accountable owner. |
| Accountable owner | The person or role responsible for a rule's continuing meaning. | Implementer | The owner answers for an approved rule. |
| Approving decision | The recorded decision that authorizes an approved rule. | Preference | A decision is required when an approved rule is recorded. |
| Covered rule | A rule exercised by at least one scenario. | Tested detail | A covered rule contributes to coverage status. |
| Coverage status | The result describing whether all approved automated rules are covered. | Test result | A catalog is covered when every approved automated rule is covered. |
| Confirmation | A clear acknowledgement before an irreversible catalog change takes effect. | Dialog control | An owner confirms deprecating an approved rule. |
